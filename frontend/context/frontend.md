# Frontend

## Stack and files
- React 19 with Vite 8, Mapbox GL JS 3, Vitest and TypeScript (strict; every source file is `.ts` or `.tsx`, no `.js` or `.jsx`), in `frontend/`. `npm run typecheck` runs `tsc --noEmit`, and the image build runs it before the tests. `src/lib` holds the logic that has tests (dates, filters, entries, layer expressions, icons, Mapbox addresses, geometry, the virtual list), `src/components` the screen, `src/styles/app.css` the look, `src/data/hot_spots.json` the four areas. `npm run dev` serves the app and sends `/tiles`, `/metadata` and `/captures` to the service on the local port set in `vite.config.ts`; `npm test` runs the unit tests; `npm run build` builds into `dist/`.
- The map is Mapbox GL JS 3, not MapLibre: the custom style is built on a Mapbox Standard import (no layers of its own), which MapLibre 6 rejected ("name: unknown property"), so the app fell back to the plain background. Mapbox GL JS reads `mapbox://` styles itself, so the address-rewriting code that MapLibre needed is gone. The map is created with `projection: "mercator"` because the Standard style defaults to a globe at low zoom.
- The reel is a fixed-height virtual list (4.375 rem per row, 70 px at the default font size), so thousands of rows cost a few dozen elements. An empty list says "No findings in this view." and a missing capture says "Image not available".
- The list is rebuilt from `queryRenderedFeatures` on the map's `idle` and `moveend` events, deduped by `id`, and only handed to the screen when the set of IDs changed.
- Checked in a real browser (headless Chromium, 29 checks) against the service on synthetic data covering all four hot spots: the week's list, the order, the panel, the popup, the fly rule, the list following the extent, the filters, the last source that cannot be unchecked, a selected pair dropped by a filter, close, and the error toast. That script lives outside the repo.

## Layout and the reel
- The slider handles are light grey with a radial gradient, a yellow ring and a 2 px grey ring (`#8b959e`, an inset `box-shadow` in `app.css`) around the light fill, so they stand out from the yellow track without the glare; an outer shadow was tried and looked like a halo.
- The layout background is `#030c13` for the page, the header, the filters, the reel and the details panel, and `#091722` for the details header, with a 1 px dark navy line (`#091722`) only under the header and on the right edge of the reel, and no border on the filters, the sort bar or the details panel; the cards in the reel keep their lighter colour, and the thin lines between the rows of the details grid stay.
- Sizes are relative: the stylesheet uses `rem` for fonts, spacing, radii and component sizes and `vw` for the three columns, and keeps pixels only for hairlines (1 to 4 px borders and outlines, shadows). One `rem` is the browser's root font size (16 px by default), so a larger browser font scales the whole screen, and the stylesheet was checked to render pixel for pixel like the old pixel version at 16 px. The reel's virtual list is the one place where JavaScript needs pixels: its row height and offset are `ROW_HEIGHT_REM` and `ROW_TOP_REM` in `lib/constants.ts`, and `remPx()` in `lib/units.ts` turns them into pixels for the scroll maths.
- The app is a React app, built with Vite. On start it shows the pairs of the last 7 days ending today (UTC); the slider runs from the earliest date in the data to today (UTC), or to the newest date in the data if that is later (`extendToToday` in `lib/dates.ts`; `/metadata` still returns the data's own range), so a week with no findings shows empty days instead of a slider that stops at the last capture, and the list and the map are empty with an empty state saying so. The layout is one grid: a header across the full width (title DarkPetro); under it the filters block, which spans the width of the reel and the details panel; under the filters the reel of entries at 15vw and the details panel at 15vw, side by side, running to the bottom of the screen; the map takes the rest of the width (70vw), from under the header to the bottom. The details panel is always there, so the map is never resized when an entry is opened; it shows the opened entry, with its capture image as a square, 75% of the panel width, at least 9rem and never wider than the panel's content (a fixed cap looked tiny on wide screens and a full-width image looked too big; the captures are square, so a 4:3 box only added dark bars and height). The filters block holds: a titled "Time range" section with the date range slider, the earliest and latest dates of the data above its two edges and the selected range written under it, then a titled "Source" section with one row holding a checkbox on the left of each source (Sentinel-1, Sentinel-2; both on by default, so several can be selected).
- The reel is ordered by capture date and time, newest first: sorted on the `t` attribute, descending, with `id` as the tie-break, so the most recent entries are at the top. Above the entries, outside the scrolling area, is a small "Sort by" drop menu with two choices, Latest (the default) and Oldest (`t` ascending); it only changes the order of the list, not the map or the filters. The icons on the map are drawn in the same order: a `symbol-sort-key` of `t` for Latest or `-t` for Oldest (a higher key is drawn on top), changed with `setLayoutProperty` when the sort changes, so the entry at the top of the reel is the icon on top, and the selected pair is drawn above all. Icons use `icon-allow-overlap` and `icon-ignore-placement`, so none is hidden.
- An entry is a rounded card a little brighter than the layout, with white text, in two rows. Row one: a small pair icon (the same SVG, drawn through a CSS mask so one file serves both colours: yellow, red when sanctioned) turned 90° clockwise, so the hulls lie one above the other with the bows pointing left, and next to it the ID, a bit bigger and in medium weight. Row two, under both, smaller and in italic, laid out as three fixed columns (the area takes the rest and is cut with an ellipsis when long, the date has 3.75rem and the source 1rem, which leaves 81 px for the area at 1366 wide, enough for the longest name ("Johor East SCS", 80 px), right aligned) so the date and the source sit at the same place on every entry whatever the length of the area name: the area, then the capture date and the source (S1 or S2, the `source` attribute in capitals). The opened entry is bright cyan with dark blue text and a dark icon, so it stands out from the others. The reel and the details panel share one minimalist scrollbar (thin thumb in the map's blue, no arrows, transparent track), so all scrolling components look the same. A CSS mask only loads over http, not from a `file://` page, so the page has to be served to be checked. The ID shown, in the reel and in the panel header, is the published `id` (`<source>_<capture time>_<hull id>`) without its first two parts, that is everything after the second underscore without a leading `w<digits>-` scene prefix, for example `33113-13846` for `s1_20261022T224733_w0-33113-13846`; the prefix is dropped because it is not part of the hull number, and all 101 real IDs stay distinct without it; it is the same ID in both places. `hull_id` is no longer a column of the published Parquet, but it is part of `id` and so is public in every tile.
- The details panel has its own header bar at the top, small and fixed: it does not move when the content below it scrolls (only the image and the grid scroll). It holds the pair icon (turned 90° like in the reel, red when sanctioned), the ID and, at the right end, a small close (x) button (a bright red cross, `#ff5c5c`, with a dark outline), then the capture image with a small muted caption under it ("Source: Sentinel-1" or "Source: Sentinel-2"; the source is not a row of the grid), then a grid with no column headers: a muted label on the left, the value on the right, with a border only under each row. Rows: the two vessels, each marked by its number in a small circle like the monitor app's (yellow when the vessel is known, that is it has a name; white with "N/A" when it is not), with each number immediately beside the vessel details; then name and a red "Sanctioned" label next to it when that vessel is sanctioned. When an IMO exists, Registration shows the IMO followed by the muted italic flag in parentheses; when only a flag exists, the flag is shown by itself. Then Capture time (date followed by UTC time) and Position (the exact `lat` and `lon` attributes, not the tile geometry, which at a low zoom is only accurate to about a kilometre). The panel content fits without scrolling at 1440x900, 1536x864 and 1920x1080 for a pair with a long name, and also at 1366x768 and 2560x1440; the image measures 154 px at 1366, 173 px at 1536, 216 px at 1920 and 288 px at 2560.
- Clicking an entry in the reel opens it in the details panel (one at a time), highlights it in the reel and, when the zoom is 10 or lower, flies the map to the pair or sanctioned vessel at zoom 11 (`FLY_ZOOM`; the tile source's last zoom is 14, so the map never overzooms its tiles). Above zoom 10 it does not fly, so a user who has already zoomed in keeps the view they have; a click on an icon on the map follows the same rule (`FLY_UP_TO_ZOOM`, `shouldFly` in `lib/geo.ts`, compared with the fractional zoom). Selecting a pair never changes the extent in any other case. Clicking a pair's icon on the map opens its entry in the details panel and scrolls the reel to it, with the same fly rule. The pair's icon on the map turns cyan (a third image, `pair-selected`, chosen by an `icon-image` expression that compares the pair `id` with the selected id) so it is easy to find; the other pairs keep yellow and red. The selection stays until the user picks another pair or presses the close button, or until the selected pair is no longer in the list (the list follows the viewport, so panning away, zooming out of it or a filter that hides it all end the selection): then the panel empties and the cyan icon goes, because details of a pair the list does not show are confusing. The check runs only once the map has settled (`idle`, so the camera has stopped and the tiles have loaded) and the list has been rebuilt from it: after a click that flies, the list does not hold the pair until then, so a fixed wait was replaced by the map's own signal (`onSettled` from `MapView`, and `flyTo` returns whether it flew; a click that does not fly is settled at once). Close clears the selection (the panel is empty again, the icon returns to its colour) and does not move the map. There is no Show on map button.
- There is no Filter button: any change to the date slider or a source checkbox applies itself 300 ms after the last change, so dragging does not send a query per step. The first render never sends a query of its own.
- The only filters are the date range and the source. `sanctioned` is shown on the entry itself and is not a filter control.

## Tabs
- The reel has two tabs at its top, Suspicious activity (the first, the pairs) and Sanctioned vessels, above the sort bar. The tab is app state (`App.tsx`); the filters (date range, source) and the sort are shared by both tabs and survive a switch.
- Switching tab clears the selection (the details panel closes and the cyan icon goes) and empties the list at once; the list is then rebuilt from the map's rendered features of the new tab's layer (`signature` is reset so the same set of IDs is not skipped). The reel scrolls back to the top.
- Each tab has its own vector source and symbol layer, ids `pairs` and `sanctioned` (the id is the tab, the source and the tile layer). A switch only changes layer visibility; the hidden layer's source stops fetching tiles (checked in a browser: after a switch only the new tab's tiles were requested). Filter changes call `setTiles` on both sources.
- A sanctioned vessel is one hull (`vessel-sanctioned` red, `vessel-selected` cyan, drawn by `vesselSvg` from the same hull path as the pair, at half the width, bow up at yaw 0). The images are registered next to the pair images in `addMapImages`. In the reel, popup and details header the icon is `sts-vessel.svg` through the same CSS mask as the pair, a wider hull than the map's so that it reads at 1.5 rem, always red.
- A sanctioned vessel's details panel is titled with the vessel's name and has, instead of the pair's numbered vessel rows (the 1/2 markers are for the two hulls the capture marks), an ID row (the short ID the pairs show as their title), a Registration row with the IMO followed by the muted, smaller, italic flag in parentheses when an IMO exists, or a Flag row when only the flag exists (the Sanctioned badge is left out because the whole tab is sanctioned), then Capture time (date followed by UTC time) and Position. Area is omitted because it is already on the entry. A sanctioned vessel's entry (reel card, hover popup and details header) is titled with the vessel's name instead of the short ID (`entryTitle`); a vessel without a name falls back to the ID. Pairs keep the short ID.
- A sanctioned vessel with an IMO has a related suspicious-activity list in its details panel. `/activities/<imo>` matches the IMO exactly against either participant of each pair finding, applies the selected date range and ignores source checkboxes. Each list row has a small yellow pair icon and ID, then the area and capture time. A small yellow pair icon also appears on vessel cards when that vessel has at least one match in the selected date range; it sits immediately left of the detection-count badge. `/activity-imos` supplies that availability set once per date range. The activity list has its own 12 rem maximum height and scrolls independently. Selecting a row keeps the sanctioned vessel selected in the reel and on the map, and adds the selected finding from `/tiles/activity/{z}/{x}/{y}.mvt` as a yellow, unselected temporary MVT overlay; its URL carries the exact activity ID and date range and omits source filters. The details show the normal activity fields and header `<vessel name>/<activity ID>`; only the vessel name is clickable and restores the saved vessel detail. Returning follows the camera rule: at zoom 10 or lower it flies to zoom 11; above zoom 10 it flies at the current zoom only if the vessel lies outside the map bounds. Closing the activity detail removes the temporary MVT source and layer.
- One vessel is one icon on the map and one card in the reel: its newest detection under the current filters (the tile carries only that one, see pipeline.md). The card shows a "×N" badge when the vessel has N detections under the filters (N includes the card's own; no badge for one). Clicking the card, or the icon on the map, selects it (cyan) and opens its history: the other detections come from `/tracks/<imo>` (fetched when the history opens, aborted when the selection or filter changes, a failed request just shows nothing) and appear in three places at once, all cleared together when the history closes or the selection goes: as icons on the map (a GeoJSON source and layer, `history`, under the cyan one) in a lighter red, `#e88f8f` against the `#d64545` of a newest detection, so they look older, as a dashed white line (`TRACK_LINE`, 2 px, dash 2-2) through every detection from the newest to the oldest, and as a list under the card.
- The history list is a box attached under the open card (the card's bottom corners are squared) whose height follows its rows (1.75 rem each plus 0.5 rem padding, `historyHeight`) up to a maximum of 5.75 rem (`HISTORY_REM`, three rows, about 10% of a 1000 px window); beyond that it scrolls, with a 0.1875 rem grey scrollbar thumb. While the list is loading the height is taken from the card's count. A row is the vessel icon in the same lighter red, the area, the date and the source in an even 0.75 rem grid, no name (it is the same vessel). The reel's rows below the open card move down by the box height: the virtual list takes one `Gap` (index and height) into its range, offset and reveal maths (`lib/virtual.ts`). Only one history is open at a time. Clicking the selected card again closes the history and keeps the selection; clicking the card of an open vessel while one of its history rows is picked selects the card again.
- Picking a history row, or a revealed icon on the map, shows that detection in the details panel and flies to it (always, even above the fly zoom, keeping the zoom then, so a detection outside the view is brought in). Clicking the picked row again (or its grey icon on the map) un-picks it: only the card stays selected, the details panel shows the vessel's newest detection again, and the map flies back to it when it is out of the view (above the fly zoom too, as for a pinned card) and otherwise follows the usual fly rule. The card stays cyan, the row gets a grey background (its icon stays the lighter red) and the picked icon on the map turns grey (`vessel-picked`). While a history is open its card stays in the reel even when the map has moved away from the vessel's newest detection (the fly to an older one usually does), so the list stays and the next row can be picked; a click on that card flies to the newest detection even above the fly zoom, since it is not in the view. A picked detection is not dropped when the map leaves it, because it is not in the reel; only a close, another selection, a filter that excludes it or a tab switch clears it. The reveal covers the vessel under the current filters, not the viewport, so a vessel seen in two hot spots gets a straight line between them (Mapbox draws lines straight in Mercator, not along the great circle). The vessel is identified by its IMO (7 digits on every sanctioned row at the time of writing). Suspicious activity pairs have no detection history; their relation to a sanctioned vessel is discovered by exact IMO in the separate activity lookup.

## Map
- Hovering a pair's icon on the map shows a Mapbox GL `Popup` (no close button, closed on mouse leave, anchored above the icon with a small offset). Its content is the same card markup as a reel entry (icon, ID, then area, date and source), so it gets the same colours, fonts and structure: the popup uses the card background (`#223c4e`), white text and rounded corners, and the tip has the same colour. The look is a CSS override of `.mapboxgl-popup-content` and `.mapboxgl-popup-tip`; the page draws the popup with the DOM MapLibre generates (`mapboxgl-popup`, `-anchor-bottom`, `-tip`, `-content`). The cursor is a pointer over an icon. Icons are small at low zoom and grow only slightly with it, so they are never huge: `icon-size` is an interpolation on the zoom, starting at 0.3 of the drawing at zoom 4 and below, 0.5 at zoom 10, 0.8 at zoom 14 and 1 at zoom 16 and above (the starting values, to be tuned on the real map).
- The list is always built from the features in the current viewport (every vessel or pair in it) and is never locked, at any zoom. After flying to a vessel the list therefore shows only what is in that small viewport; the user pans and zooms freely at every zoom. There is no Back to query area button: it was dropped together with the stored query area and the zoom threshold 13 it used.
- Basemap: a Mapbox style drawn by Mapbox GL JS, with the public token as `accessToken`. The style is `VITE_MAPBOX_STYLE` (a `mapbox://styles/<account>/<id>` address or `<account>/<id>`), and when it is not set the Navigation Night style `mapbox/navigation-night-v1` is used (`lib/mapbox.ts`). The token is a public one (`pk.`), which the browser can see by design, so only a public token is ever used, never a secret one (`sk.`), and it should be restricted to the viewer's address in the Mapbox account. Nothing credential-like or account-specific is committed: the token is `MAPBOX_ACCESS_TOKEN` and the style is `MAPBOX_STYLE` in the git-ignored `deploy/deploy.env` (`deploy.sh` and `compose.yaml` hand them to the image build as `VITE_MAPBOX_TOKEN` and `VITE_MAPBOX_STYLE`), and `VITE_MAPBOX_TOKEN` and `VITE_MAPBOX_STYLE` in the git-ignored `frontend/.env.local` for local work; the repo holds only placeholders, and the built `frontend/dist` and the image, which contain both, must not be published. Mapbox GL JS bills per map load under Mapbox's terms, and visitors' requests, including their IP addresses, go to Mapbox. Without a token the app shows a plain background (the style address is only built when there is a token). If the style fails to load the app shows a toast and falls back to the plain background. The Mapbox and OpenStreetMap attribution and the Mapbox logo are shown. The icons carry outlines so they read on any basemap.
- Rotation and tilt are blocked (drag and touch rotation off, keyboard rotation off, `maxPitch` 0). The map is not enabled for touch: the viewer is for a mouse and keyboard, so the hover popup needs no touch variant.
- Map controls stay, restyled in the dark theme: the navigation control with zoom in and out (no compass, since rotation is off), the scale bar at the bottom left and the attribution at the bottom right.
- When the filter changes, a selected pair whose `date` or `source` falls outside the new filter is dropped: the details panel closes and the cyan icon goes. The app can decide this from the selected pair's own attributes, without querying.
- Errors (a tile request or `/metadata` failing) show in a toast at the top centre of the map, in the dark theme with a red accent and a close (x) button, and go away by themselves after a few seconds.
- The fly rule compares `map.getZoom()` as it is, fractional: flying to zoom 11, and only up to zoom 10 (see Layout and the reel).
- Tile layers `pairs` and `sanctioned` (see Tabs), one point per finding; there are no `links` layers. The app draws a two-vessel icon at the pair position: two identical silhouette hulls side by side, a pointed bow and a blunt stern like the ships in the capture image, drawn at yaw 0 with both bows pointing south (`frontend/src/assets/icons/sts-pair.svg`). The map rotates it with `icon-rotate: ["get", "yaw"]` and `icon-rotation-alignment: map`, so the angle is measured from north.
- The icon is not a fixed file: the frontend has an SVG creator function that takes parameters such as the colour and the base orientation and returns the SVG for them. A symbol layer cannot use an SVG directly, so when the map loads the app builds one image per colour (the SVG through an `Image` with explicit size, at 2x or 3x pixel ratio) and registers each with `map.addImage`; nothing is redrawn while the app runs. There are three colours, and a colour applies to both hulls of a pair: yellow (`#f2c230`, blue was dropped because it is too close to the ocean colour) when sanctioned is false or unknown, red (`#d64545`) when either vessel is sanctioned, i.e. when the tile attribute `sanctioned` is true. The style picks the image with `icon-image: ["case", ["get", "sanctioned"], "pair-sanctioned", "pair"]`. Per-pair rotation is not done by redrawing: it stays in the style, driven by `yaw`. On the map the icons carry an outline so they stay visible on any basemap: black around yellow and red, white around the cyan selected pair (cyan `#4fd0e4`, the third image `pair-selected`); the creator takes the fill and the stroke as parameters. The icons in the reel and the details panel have no outline.
- The hot-spot boundaries are white lines (2 px, full opacity) and the pair icons are drawn on the `top` slot with an emissive strength of 1. The custom style has lights and a Standard import, which darken and bury layers that have no slot or emissive strength: the lines used to show as a faint grey. There is no animation when a query adds or removes pairs: fades were tried (the whole layer, then only the pairs that differ between the old and the new filter) and dropped, because the icons then appeared and disappeared later than the data.
- The four hot-spot areas stay: their boundaries and names are drawn from `frontend/src/data/hot_spots.json` (`fujairah_outer`, `off_sohar`, `malaysia_eopl`, `johor_east_scs`) at every zoom, with no fill logic or counts, whether or not they hold data.
- The hot-spot areas are the monitor's own site rectangles (name plus bounding box, in its `sts_watch` rules). This repo owns a copy of only the names and boxes, never the monitor's explanatory text: `frontend/src/data/hot_spots.json`, a GeoJSON polygon per hot spot, copied once from the monitor's rules and edited here from now on. `malaysia_eopl` and `johor_east_scs` touch along one edge. Both were widened west from 103.5°E to 103.4°E and `johor_east_scs` north from 2.8°N to 3.3°N, because the monitor assigns a finding to a hot spot by its scene and two published findings (103.48°E, 1.25°N and 104.97°E, 3.22°N) fell outside the original rectangles; every one of the 101 findings now lies inside its own box.
- Start view: the app fits the four hot-spot boxes with padding for the reel, capped at zoom 4, so that all four are visible whatever the screen width. A fixed zoom 4 centred at about 81.1°E, 13.3°N only shows all four when the map area is about 1250 px wide, which with a reel of about 450 px needs a window wider than about 1700 px.
- Dates are UTC everywhere, including "last week" at start and the slider labels. They are shown as `DD.MM.YYYY` (for example `01.09.2026`); the `date` tile attribute and the filter parameters stay `YYYY-MM-DD`.
- There is no clustering for now. The tiles carry every finding at every zoom and the map draws all of them, with no limit and no hiding; if the map gets cluttered, narrowing the filters is the user's job. Clustering is parked, not dropped: it still makes sense and needs refining before it is built. The idea, as far as it was designed: the app groups the pairs in view into clusters in the list only (never in the MVT), each tied to an area it draws as a GeoJSON polygon; below zoom 10 the four hot-spot areas, at zoom 10 to 13 four quadrants (NE, SE, SW, NW) cut from the centre of a hot spot, from zoom 14 circles named A, B, C from west to east, each level shown only above a threshold of 20 pairs on the display; clicking a cluster flies to its area. The full wording is in this file at commit `184f24c`.
